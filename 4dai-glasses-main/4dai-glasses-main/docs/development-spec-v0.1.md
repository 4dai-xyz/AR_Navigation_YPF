# AI 智能眼镜开发规格 V0.1

更新时间：2026-05-09

## 1. 文档目的

本文档用于把当前仓库已经落地的实现边界、默认演示链路、保留能力和交付口径收敛成统一开发规格，供 Android、Cloud、Mapping 和文档维护共同遵守。

本文档描述的是当前代码事实，不等同于最初的长期产品愿景。凡是“保留能力”“调试链路”“未来恢复”的内容，都不能被表述成当前默认主流程。

## 2. 当前实现基线

当前仓库已经收口为以下口径：

- 室外主链路：Android App 已接入真实高德导航，支持室外 POI 搜索、当前位置、骑行/步行路线、导航视角切换和退出导航。
- 室内主链路：`Enter Venue` 后切换到高德室内底图，并进入 `manual_demo` 手动演示模式。
- 室内交互方式：通过方向键、楼层键、重置和退出按钮推进室内演示，不默认依赖云端重定位结果。
- 室内样例场馆：北京五道口购物中心西门到 2F TATA 店铺门口已固化为当前默认脚本。
- Android 调试增强：室内点位标注、路线校准层复用、本地图纸路径规划和图片底图预览已接入。
- 云端能力：`visual-locate`、`indoor-route`、OpenAPI、错误码、日志、超时和置信度策略仍保留在仓库中，但默认不作为当前室内主演示链路。
- 建图能力：样例场馆包、校验脚本、发布脚本、离线评估脚手架、五道口 route-only 草案和真实场馆准备文档已具备，但首个真实场馆正式包尚未入库。

## 3. 当前范围

### 3.1 当前包含

- Android 手机端作为主交互终端
- 真实高德室外导航
- 高德室内底图显示
- 室内 `manual_demo` 手动演示模式
- 室内调试面板
- 室内路线校准层与本机复用
- 五道口 B1/F1 本地图纸路径规划 Debug
- 云端服务骨架与接口工程
- 场馆地图包规范、样例、校验和发布工具
- 离线重定位评估脚手架

### 3.2 当前不包含

- 眼镜端独立运行
- 室外到室内自动切换
- 当前默认启用的云端视觉重定位室内主流程
- 当前默认启用的真实室内自动路径规划演示
- 多场馆在线切换平台
- 真实订单自动带入

## 5. 子项目边界

### 5.1 Android

Android 子项目负责当前默认演示体验：

- 室外高德导航
- 室内底图展示
- `manual_demo` 状态机与操作壳子
- Debug 面板
- 室内路线校准层
- 本地图纸路径规划调试视图与本地路网加载
- 本地参数持久化和联调入口

Android 当前不能把“云端定位成功”写成室内默认前提。

### 5.2 Cloud

Cloud 子项目负责保留的服务能力：

- `health`
- `venue meta`
- `visual-locate`
- `indoor-route`
- 错误码、超时、日志和置信度策略

Cloud 当前是“可联调、可保留、可恢复”的能力，不是当前室内主演示的默认依赖。

### 5.3 Mapping

Mapping 子项目负责场馆数据生产能力：

- S20 到场馆包的生产流程文档
- 场馆包样例
- 五道口 route-only 草案与 App handoff 数据
- 校验脚本
- 发布脚本
- 离线评估脚手架

Mapping 当前更多承担“真实场馆数据准备”和“恢复云端重定位链路”的底座职责。

### 5.4 Contracts & Docs

Contracts 与 Docs 负责三方共享事实源：

- OpenAPI 契约
- 场馆地图包规范
- 总体 PRD、开发规格、架构和测试模板

一旦字段或链路口径发生变化，必须同步更新文档，不允许 Android、Cloud、Mapping 各自维护不同版本的真相。

## 6. 当前运行链路

### 6.1 默认演示链路

1. 用户在 App 中搜索或选择目标店铺/入口。
2. App 调用真实高德完成室外骑行或步行导航。
3. 到达入口附近后，演示人员手动点击 `Enter Venue`。
4. App 切换到高德室内底图。
5. App 进入 `manual_demo`，显示目标、当前位置摘要、方向提示和楼层按钮。
6. 演示人员通过上下左右和楼层按钮推进室内导航演示。
7. 到达目标后，可重置或退出室内模式。

### 6.2 保留调试链路

1. Debug 面板可触发 `Capture & Locate`。
2. Debug 面板可触发 `Request Route`。
3. Cloud 服务可返回室内定位和路径规划结果。
4. 该链路当前默认关闭，不参与室内主界面的第一层操作流。

### 6.3 当前场馆样例调试链路

1. App 从 Android assets 加载五道口 B1/F1 的本地图纸、路网和 resolver。
2. 用户可在本地图片底图上搜索目标，如 `nike / starbuck / ruixing`。
3. App 基于本地 `image_pixel` 路网执行路径规划。
4. 室内路线校准层可把当前路线按楼层保存为本机 GCJ-02 叠加点。
5. 已保存楼层优先显示到高德室内底图，未保存楼层继续使用本地图纸预览兜底。

该链路用于 App 与 Mapping 的集成调试，不替代正式场馆包或云端默认室内主流程。

## 7. 数据与契约约束

### 7.1 场馆包是共享事实源

以下数据必须以场馆包或其标准化产物为准：

- `venue_id`
- `floor_id`
- `poi_id`
- `entrance_id`
- `connector_id`
- `route_graph`

Android、Cloud、Mapping 不得各自维护不同版本的 POI、楼层和路网真相。

Android assets 中的 `mapping/wudaokou/*` 属于 Mapping 向 App 交付的调试集成产物，不替代正式场馆地图包规范，也不能被写成当前正式发布包。

### 7.2 契约文件必须一致

以下文档必须保持字段语义一致：

- `contracts/venue-package/venue-map-package-spec-v0.1.md`
- `contracts/openapi/indoor-navigation-api-v1.yaml`
- `cloud/docs/cloud-localization-api-draft-v0.1.md`

### 7.3 室内模式口径必须一致

以下文档必须统一使用当前口径：

- 当前默认室内模式为 `manual_demo`
- 当前默认室内进入方式为手动 `Enter Venue`
- 云端视觉重定位与室内路径规划是保留能力，不是当前主演示链路

## 8. 验证口径

当前开发规格阶段的最低验证口径如下：

- Android：`assembleDebug` 通过
- Android：`testDebugUnitTest` 可执行并与当前仓库测试现状一致
- Mapping：样例场馆包可通过校验与发布脚本
- Cloud：基础编译与核心契约/单测可运行
- 文档：总 README、各子项目 README/PROGRESS 与公共规格口径一致

## 9. 交付定义

当以下条件同时满足时，可认为当前开发规格已与仓库状态对齐：

1. 总体文档明确区分“默认演示链路”和“保留调试链路”。
2. Android 文档明确当前室内默认模式为 `manual_demo`。
3. Cloud 文档明确当前能力为保留可联调能力，而非当前主流程依赖。
4. Mapping 文档明确当前样例和工具已就位，但真实场馆数据仍待补齐。
5. 测试模板能够覆盖当前默认演示模式和 Debug 联调模式。
