# Android App 最终 UI 交付规范 v0.1

更新时间：2026-05-08

## 1. 文档定位

本文档用于把当前 Android App 的最终 UI 方向沉淀为可直接交付开发的实现规范。目标不是给出“设计意图”，而是给出足够精确的页面、组件、交互、视觉和验收说明，使开发者或开发者 AI 可以在不二次猜测的前提下实现与参考方案高度一致的界面。

本文档覆盖：

- 室外搜索与目标确认
- 室外导航与场馆交接
- 室内导航主界面
- 隐藏式 Debug 入口与手动演示控件
- 外部高德导航按钮与回流逻辑
- 页面视觉系统、尺寸、颜色、排版、动效与文案规则

本文档不覆盖：

- 云端接口协议本身
- 高德 SDK 初始化细节
- Mapping 数据生产细节
- 眼镜端 UI

## 3. 产品口径与实现假设

本批 UI 必须建立在以下事实之上：

- 当前产品主交互终端是手机 App，不是眼镜端显示。
- 当前主流程是“室外到入口 -> 手动进入场馆 -> 室内导航”。
- 当前室内默认主链路是 `manual_demo`，不是云端重定位。
- Debug 能力必须保留，但不能在首层主界面显眼暴露。
- 外部高德导航跳转能力已存在，最终版 UI 只需要把它收口为产品化入口。

本文档中所有“室内自动切换”“自动判断已到入口”等描述都不得写成当前已实现事实。任何文案都不能暗示这些能力已经完成。

## 4. 最终版 UI 原则

### 4.1 地图优先

无论室外还是室内，地图都是页面的主角。任何卡片、表单、结果列表或调试面板都不得长期占据地图的大面积可视区域，除非用户主动进入搜索或调试流程。

### 4.2 单主动作优先

每个主要页面底部只允许存在一个绝对主动作。次级动作可以存在，但数量必须严格受控：

- 常规页面：`1 个主动作 + 0~2 个辅动作`
- 搜索结果页：列表项本身即主要交互，不再额外叠加大量并列按钮
- 调试态：进入二级层后可放宽，但也要控制层级

### 4.3 调试隐藏

调试入口不是删除，而是收纳到不打扰主流程的隐藏层：

- 默认不可见
- 通过长按触发
- 先弹出轻量 Debug Drawer
- 再进入十字方向键与楼层控件

### 4.4 骑手场景优先

目标用户是赶时间、单手操作、经常边走边看的骑手，因此必须满足：

- 主要点击区域大
- 文案短
- 结果可快速扫读
- 室外到室内切换语义明确
- 到达入口与到达店铺是两件不同的事，UI 必须明确区分

## 5. 设计基线

### 5.1 目标设备基线

- 设计基线：`1080 x 2400 px`
- 实现基线：Android `dp/sp`
- 屏幕方向：仅纵向
- 适配范围：主流 Android 1080p 与 1440p 机型，优先保证 `360dp~412dp` 宽度表现

### 5.2 安全区与边距

- 顶部安全边距：状态栏下方至少 `12dp`
- 页面左右基础边距：`16dp`
- 底部 Dock 距离导航栏安全边距：`12dp`
- 浮层之间最小垂直间距：`12dp`

### 5.3 间距系统

仅使用以下间距档位：

- `4dp`
- `8dp`
- `12dp`
- `16dp`
- `20dp`
- `24dp`
- `32dp`

不允许出现随机 `7dp`、`11dp`、`15dp` 之类的值。

## 6. 视觉系统

### 6.1 色彩

主色必须克制、偏中性，不走高饱和科技风，不使用偏紫主基调。

#### 文字色

- 主文字：`#111827`
- 次文字：`#374151`
- 弱文字：`#6B7280`
- 反白文字：`#FFFFFF`

#### 品牌与强调色

- 主强调色：`#1F8A70`
- 主强调色按下态：`#166A56`
- 地图交互蓝绿色辅助色：`#59C3C3`
- 链路高亮线色：`#2F80ED`

#### 背景与表面

- 页面底色：`#F6F5F1`
- 浮层主表面：`#FDFDFB`
- 浮层半透明表面：`#FDFDFBE6`
- 分隔线：`#E5E7EB`
- 输入底色：`#F3F4F6`

#### 状态色

- 成功：`#1E8E5A`
- 提醒：`#D97706`
- 错误：`#C2410C`
- 低置信度辅助底：`#FFF4E5`

### 6.2 字体与排版

默认使用系统无衬线字体即可，但排版风格必须接近参考图中的紧凑精致感。

- 大标题：`22sp / Semibold / 行高 28sp`
- 胶囊主标题：`18sp / Semibold / 行高 24sp`
- 列表标题：`16sp / Semibold / 行高 22sp`
- 正文：`14sp / Regular / 行高 20sp`
- 辅助信息：`12sp / Regular / 行高 16sp`
- 按钮主文案：`16sp / Semibold`
- 按钮辅文案：`14sp / Medium`
- 标签/Chip：`12sp / Medium`

规则：

- 同一层内不超过 3 个字号
- 不允许大段多行说明文字堆在主界面上
- 胶囊内文本最多 3 行

### 6.3 圆角

- 搜索胶囊：`24dp`
- 顶部状态胶囊：`24dp`
- 底部主 Dock：`28dp`
- 结果页大面板：顶部圆角 `28dp`
- 二级调试抽屉：顶部圆角 `24dp`
- 单个按钮：`18dp`
- 小 Chip：`14dp`

### 6.4 阴影与层级

地图为底层，所有浮层采用柔和阴影，不可出现重黑阴影。

- 顶部状态胶囊：中等阴影
- 底部 Dock：中高阴影
- 搜索结果大面板：高于状态胶囊
- 手动控件面板：高于普通 Dock
- Debug Drawer：低于手动控件面板，但高于地图

### 6.5 图标

建议统一使用 `Material Symbols Rounded`，保持温和圆角风格。

建议使用的图标名称：

- 搜索：`search`

- 清除：`close`
- 定位：`my_location`
- 北向/车头：`explore`
- 全览：`zoom_out_map`
- 更多：`more_horiz`
- 继续：`arrow_forward`
- 进入场馆：`meeting_room`
- 店铺：`storefront`
- 商场入口：`location_on`
- 写字楼：`apartment`
- 小区：`home_work`
- 调试：`tune`

## 7. App Shell 布局总则

### 7.1 三层结构

最终主页面维持三层，但表现形式从“大卡片控制台”改为“地图主界面 + 轻浮层”：

1. 底层：地图宿主
2. 中层：顶部胶囊 / 浮动按钮
3. 顶层：底部 Dock / Bottom Sheet / Debug Drawer

### 7.2 室外地图宿主

- 使用现有 `AMapNaviView`
- 保持全屏铺满
- 搜索态允许被搜索结果面板覆盖
- 非搜索态不允许出现大面积白底表单

### 7.3 室内地图宿主

- 使用现有普通 `MapView` 或其当前宿主方案
- 显示室内底图、路径高亮、目标点和当前点
- 底部面板默认不能把地图遮挡到只剩很小一块

### 7.4 顶部状态胶囊

#### 位置

- 顶部安全区以下 `12dp`
- 左右各 `16dp`
- 宽度跟随内容，但最大不超过屏宽减去左右边距

#### 内容结构

- 第一行：阶段标签 + 楼层 Chip 或 ETA Chip
- 第二行：当前最重要的导航标题
- 第三行：必要时的简短说明

#### 样式规则

- 背景：浅色半透明表面
- 背景模糊：若实现成本高，可退化为纯浅色不透明
- 内边距：`14dp 16dp`
- 行间距：`4dp`

### 7.5 底部主 Dock

#### 位置

- 底部安全区以上 `12dp`
- 左右各 `16dp`

#### 形态

- 大号圆角胶囊或半浮岛式容器
- 单层结构优先
- 默认高度 `84dp~96dp`

#### 内容规则

- 主按钮必须明显
- 辅助操作最多 2 个
- 如果辅助操作超过 2 个，必须收进 `更多`

### 7.6 浮动地图控件

只保留合理的地图级控件：

- 回到当前位置
- 方向模式切换
- 全览

室内状态默认仅保留：

- 回到当前位置
- 必要时保留全览

不允许在室内界面继续保留看起来像室外导航专用的按钮组。

## 8. 搜索与目标输入逻辑

### 8.1 顶部类型按钮

搜索页顶部提供 4 个类型按钮：

- `店铺`
- `商场入口`
- `写字楼`
- `小区`

它们是同一个搜索系统的筛选器，不是 4 套完全独立流程。

### 8.2 各类型功能逻辑

#### `店铺`

- 默认高亮
- 搜索目标是门店、品牌店、餐饮店、商铺
- 选中后必须尝试解析：
  - 店铺名
  - 所属场馆
  - 最近可进入入口
  - 室内目标 `target_poi_id`
- 室外导航落点：场馆入口
- 室内导航落点：店铺门口

#### `商场入口`

- 搜索目标是商场、综合体、入口点
- 结果优先展示具体入口而不是整栋建筑
- 选中后直接将室外导航终点设置为该入口
- 默认不附带室内目标

#### `写字楼`

- 搜索目标是大厦、办公楼、园区、写字楼大厅或入口
- 第一版默认把它视为“建筑入口到达”
- 若该写字楼存在场馆包，再允许进入室内导航
- 若无室内数据，则在入口完成室外流程

#### `小区`

- 搜索目标是小区、大门、门岗、南门/北门/西门等入口
- 第一版只做到“小区入口到达”
- 默认不进入室内链路

### 8.3 搜索结果页的落点解释规则

开发时必须把“选中项”与“室外终点”区分：

- 店铺：选中的是店铺，导航到的是入口
- 商场入口：选中和导航终点相同
- 写字楼：选中的是楼宇，导航到的是楼宇主入口
- 小区：选中的是小区或门点，导航到的是门点

## 9. 页面定义

以下页面定义以“交互意图 + 视觉结构 + 必要控件 + 禁止事项”的方式描述。

### 9.1 S01 搜索首页

#### 目的

让用户快速开始搜索，而不是先看一堆参数面板。

#### 视觉结构

- 全屏地图为底
- 顶部搜索胶囊位于状态栏下方
- 搜索胶囊下方是 4 个类型按钮
- 页面下半部分仅轻量展示最近到达、常用目的地或最近搜索

#### 搜索胶囊

- 左侧：搜索图标
- 中间：占位文案 `搜索目的地`
- 右侧：可选清除按钮或语音占位，当前版本可不做语音
- 高度：`52dp`

#### 类型按钮

- 单行横向排列
- 默认高亮 `店铺`
- 其余为浅色描边或浅底
- 点击切换搜索筛选，不切换页面

#### 不允许

- 不允许首屏暴露 `baseUrl / venue_id / poi_id`
- 不允许出现明显的调试按钮
- 不允许底部堆满卡片

### 9.2 S02 搜索结果页

#### 目的

解决“结果太少”的问题，让用户可以一屏快速扫读足够多的候选项。

#### 视觉结构

- 顶部保留搜索胶囊与类型按钮
- 主体是近乎独立的高密度结果列表面板
- 地图只在背景或顶部轻微露出，不再占主区域

#### 结果列表要求

- 一屏可见 `6~8` 条结果
- 单条高度建议 `68dp~76dp`
- 每条结果结构：
  - 第一行：地点名
  - 第二行：类型标签 + 地址或所属区域
  - 右侧：距离
  - 可选极简箭头或“导航”提示

#### 点按规则

- 点击整行：选中结果并进入目标确认页
- 不建议在列表项里同时放多个大按钮
- 若保留右侧小型“导航”入口，它只是快捷动作，不能喧宾夺主

#### 列表表现

- 列表面板顶部显示 `搜索结果`
- 允许滚动
- 滚动时顶部搜索胶囊固定

#### 权威视觉参考

- 以 `05-search-results-dense-board.png` 为准

### 9.3 S03 目标确认页

#### 目的

在用户选中结果后，明确“你要去哪里”和“室外实际导航到哪里”。

#### 核心文案关系

对于 `店铺` 类型，必须明确显示：

- 目标店铺
- 所属场馆
- 最近入口

建议表现：

- 顶部小胶囊：当前阶段
- 中部地图：入口路线预览
- 底部确认区：
  - 主按钮：`前往入口`
  - 次按钮：`高德导航`

#### 按钮逻辑

- `前往入口`
  - 进入 App 内室外导航主流程
- `高德导航`
  - 直接跳转外部高德 App

#### 文案要求

- 不能把“店铺门口”误写成当前室外终点
- 必须清楚区分“入口”与“店铺”

### 9.4 S04 室外路线已就绪页

#### 目的

显示入口路线已准备完成，等待开始导航。

#### 结构

- 地图占主视觉
- 顶部状态胶囊显示：
  - 目标入口
  - 预计时间
  - 剩余距离
- 底部 Dock：
  - 主按钮：`开始导航`
  - 次按钮：`打开高德`

#### 特殊规则

- 若当前已经是外部高德会话，次按钮文案改为 `继续高德`

### 9.5 S05 接近入口 / 场馆交接页

#### 目的

让用户明确知道：室外目标不是店铺，而是入口；到入口后才进入室内链路。

#### 结构

- 地图仍为主视觉
- 顶部胶囊显示接近入口状态
- 底部 Dock：
  - 主按钮：`进入场馆`
  - 次按钮：`继续高德` 或 `稍后进入`

#### 进入条件

- 可以是用户手动点击
- 如果来自外部高德回流，且距离入口足够近，也进入该页

#### 不允许

- 不要使用“已自动进入室内”之类文案

### 9.6 S06 室内导航主界面

#### 目的

把室内引导做成正式产品界面，而不是调试台。

#### 结构

- 室内地图全屏
- 顶部状态胶囊：
  - 左：阶段标签 `室内导航`
  - 右：楼层 Chip，例如 `F2`
  - 标题：下一步指令，例如 `继续直行`
  - 必要时补充一行简短说明
- 右下浮动按钮：
  - 回到当前位置
- 底部 Dock：
  - 左：`上一步`
  - 中：主按钮 `继续`
  - 右：`更多`

#### 关于 `继续`

在当前 `manual_demo` 模式下，`继续` 不是自由移动，而是推进当前脚本期望动作的主入口。若当前步骤不是直行，而是左转、右转或上楼，不要假装 `继续` 可以解决一切，必须通过 `更多` 展开手动控件。

### 9.7 S07 低置信度辅助页

#### 目的

当保留链路触发低置信度时，给出冷静、产品化的辅助提示，而不是大段错误日志。

#### 结构

- 室内地图仍保留
- 顶部胶囊变成提醒态
- 底部主按钮：`补拍一张`
- 次动作：`稍后再试`

#### 表现

- 使用浅橙色提示底
- 文案简短，例如：
  - `定位不够稳定，请补拍一张环境照片`

### 9.8 S08 到达页

#### 目的

明确告诉用户已经到达店铺门口。

#### 结构

- 地图仍可见
- 顶部胶囊或中上部简洁成功提示：
  - `已到达`
- 底部主按钮：
  - `完成`

#### 视觉要求

- 成功感克制
- 不要做过度庆祝式动画

### 9.9 S09 隐藏 Debug Drawer

#### 目的

保留工程调试链路，但不破坏正常产品观感。

#### 触发方式

- 长按顶部状态胶囊 `1500ms`
- 或长按顶部极小品牌点 `1500ms`

建议只保留一种正式手势，以免误触。

#### 反馈

- 长按 600ms 后给出极轻微触觉反馈或视觉细线提示
- 满足触发阈值后，从底部拉起窄版 Drawer

#### Drawer 内容

只放轻量入口，不直接露出整屏日志表单：

- `手动演示`
- `采图定位`
- `切换 Provider`
- `联调参数`
- `查看日志`

#### 不允许

- 默认常驻显示
- 大面积日志墙直接覆盖主界面

### 9.10 S10 十字方向键与楼层控件面板

#### 目的

把当前必须保留的 `manual_demo` 操作能力放进二级层，而不是首层界面。

#### 打开方式

- 在 Debug Drawer 中点击 `手动演示`
- 从底部弹出扩展控制面板

#### 面板结构

- 中部：十字方向键
  - `上`
  - `左`
  - `右`
  - `下`
- 下方：楼层操作
  - `上楼`
  - `下楼`
- 最下方：次要控制
  - `重置`
  - `退出室内`

#### 表现要求

- 面板本身要精致、克制
- 不能做成老式遥控器或游戏手柄风格
- 默认隐藏

#### 权威视觉参考

- 以 `06-hidden-debug-controls-board.png` 为准

## 10. 外部高德导航按钮

### 10.1 功能要求

UI 中必须显式提供“跳转外部高德 App 进行导航”的按钮。

### 10.2 放置位置

至少出现在以下页面：

- S03 目标确认页
- S04 室外路线已就绪页
- S05 接近入口页

### 10.3 文案规则

- 初始：`高德导航` 或 `打开高德`
- 已有外部高德会话：`继续高德`

### 10.4 交互逻辑

- 点击后调起高德 App
- 返回本 App 后检查是否接近入口
- 若已接近入口，进入 S05
- 若仍较远，保留继续导航入口
- 若调起失败，给出轻量错误提示并保留 App 内导航入口

## 11. 页面动效规则

### 11.1 时长

- 快速微动效：`160ms`
- 普通过渡：`220ms`
- 底部面板弹出：`280ms`

### 11.2 曲线

- 推荐 `FastOutSlowIn`

### 11.3 必做动效

- 搜索结果页从底部或右侧轻滑进入
- 目标确认页平滑切换，不突兀闪屏
- Debug Drawer 从底部上滑
- 手动控件面板在 Debug Drawer 之上继续上滑展开

### 11.4 不做

- 不做花哨粒子效果
- 不做明显科幻 HUD 动画
- 不做夸张弹跳

## 12. 文案规范

### 12.1 用词统一

- 室外目标：`入口`
- 室内目标：`店铺门口`
- 进入室内动作：`进入场馆`
- 外部高德动作：`高德导航` / `继续高德`

### 12.2 禁止误导文案

以下文案不能出现：

- `自动进入室内`
- `实时室内定位稳定运行中`
- `眼镜导航已接入`

### 12.3 建议文案

- 搜索页：`搜索目的地`
- 入口确认：`前往入口`
- 场馆交接：`进入场馆`
- 到达：`已到达`
- 室内提示：`继续直行`、`前方左转`、`乘扶梯上楼`

## 13. 与现有代码结构的对齐要求

实现时必须尽量复用当前状态与能力，不允许为了追求视觉整洁而删除已有主链路。

必须保留：

- 室外高德导航
- 室内底图宿主
- `manual_demo`
- Debug 保留链路
- 外部高德导航

建议的结构对齐：

- 顶部状态胶囊：承接 `TopCardUiModel`
- 底部主 Dock：承接 `BottomActionBarUiModel`
- 地图浮动按钮：承接 `MapChromeUiModel`
- 隐藏 Debug Drawer：承接现有 `DebugPanelUiModel`，但改成隐藏触发和轻量入口形态

## 14. 验收标准

### 14.1 视觉验收

- 首屏不再像联调控制台
- 顶部从大状态卡变为紧凑胶囊
- 底部只有单主动作和少量辅动作
- 搜索结果页一屏可见至少 6 条结果
- 室内十字方向键不在默认主界面暴露

### 14.2 交互验收

- 用户能从搜索首页进入结果页，再进入目标确认页
- `店铺` 类型会先导航到入口，再进入室内
- 外部高德按钮可见且语义清晰
- 长按可触发隐藏 Debug Drawer
- 可从 Debug Drawer 再展开手动十字方向键

### 14.3 事实口径验收

- 不夸大当前自动化能力
- 不把 Debug 链路冒充成首层主流程
- 不删除当前必须保留的联调能力

## 15. 不得偏离的实现结论

以下结论为本批 UI 的强约束：

- 搜索结果页必须采用高密度主结果页，而不是小抽屉
- `店铺 / 商场入口 / 写字楼 / 小区` 是搜索筛选器，不是 4 套互不相干页面
- 外部高德导航按钮必须进入正式 UI
- `manual_demo` 控件必须二级隐藏，不得首层常驻
- 默认主界面要看起来像正式产品，而不是调试版
