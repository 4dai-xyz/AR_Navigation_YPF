# Android 室内手动演示模式方案 v0.1

更新时间：2026-05-05

## 1. 需求变更摘要

室内导航阶段的当前目标从“云端重定位联调演示”调整为“手动交互演示”：

- 云端视觉重定位与室内路径规划代码暂时保留
- 默认不接入、不触发、不作为当前 Demo 主链路
- 室内阶段由人工按键驱动，模拟走动、转向、跨层和到店过程
- 高德室内底图继续作为室内展示底图

这次调整的本质不是删除原方案，而是把当前室内 Demo 主链路切换为 `manual_demo`。

## 2. 目标

本方案要解决的是“在没有稳定真实重定位链路时，如何把室内导航 Demo 演示顺畅、可控、可重复”。

首版目标：

- 进入室内后，App 展示高德室内底图
- 屏幕提供十字布局的 `上 / 下 / 左 / 右` 和 `上楼 / 下楼` 按钮
- 用户按键后，App 按预设脚本推进室内导航状态
- 顶部状态卡和地图同步展示当前提示、当前楼层、当前位置和目标点
- 手动演示过程不依赖云端实时定位结果

## 3. 不做范围

- 不删除现有云端定位与室内路径规划代码
- 不要求真实眼镜图片链路参与室内主流程
- 不做自由漫游式室内定位
- 不做用户任意点选后的动态重算路
- 不做自动楼层识别

## 4. 总体设计

室内运行模式拆成两个概念：

- `MANUAL_DEMO`
  - 当前默认模式
  - 不调用云端重定位
  - 不调用云端室内路径规划
  - 使用预置路线脚本 + 手动按键推进

- `CLOUD_RELOCALIZATION`
  - 代码保留
  - 默认关闭
  - 不作为当前演示入口

建议 App 内引入一个显式模式字段：

```text
IndoorNavigationMode =
  "manual_demo" |
  "cloud_relocalization"
```

当前版本默认值固定为：

```text
manual_demo
```

## 5. 演示链路

当前推荐的完整演示链路如下：

1. 室外阶段继续使用现有高德室外导航
2. 用户到入口后点击 `Enter Venue`
3. App 切入室内底图界面
4. App 加载预设的室内演示脚本
5. App 显示当前楼层、当前点位、目标点、预设路线和第一条导航提示
6. 用户按 `上 / 左 / 右 / 下 / 上楼 / 下楼`
7. App 根据脚本推进到下一步，更新提示、位置、楼层和路径高亮
8. 到达终点后显示“已到达店铺门口”

## 6. 按键语义

### 6.1 方向键

方向键不是自由移动地图，而是“推进预设导航脚本”的输入器。

- `上`
  - 含义：直行 / 前进 / 通过当前路段
  - 用于“直行 10 米”“继续前进”“通过当前走廊段”等步骤

- `左`
  - 含义：执行左转
  - 用于“前方左转”“左转后继续直行”等步骤

- `右`
  - 含义：执行右转
  - 用于“前方右转”“右转后继续直行”等步骤

- `下`
  - 含义：回退一步
  - 用于演示中纠错或回到上一个脚本节点

### 6.2 上楼 / 下楼键

`上楼 / 下楼` 用于模拟跨层动作，不由定位自动决定。

示例：

- 当前提示为“乘电梯到 2 楼”
- 用户点击 `上楼`
- App 切换到 2 楼高德室内底图
- 当前点位、目标点和路线切片同步切到 2 楼
- 顶部提示切换为“已到 2 楼，继续直行”

## 7. 交互规则

### 7.1 正确输入

当用户按下当前步骤所期待的按键时：

- 脚本推进到下一步
- 顶部状态卡更新为下一条提示
- 地图上的当前位置移动到下一节点
- 若涉及楼层变化，则切换到对应楼层

### 7.2 错误输入

当用户按下非预期按键时：

- 不推进脚本
- 顶部状态卡显示“当前应执行：右转”之类的纠错提示
- 当前位置保持不变
- 日志中记录一次 `manual_demo_wrong_action`

### 7.3 回退

按下 `下` 时：

- 回退到上一步脚本节点
- 恢复上一条导航提示
- 当前位置与路径高亮回退
- 若跨楼层回退，则同步回到上一楼层

## 8. 路线脚本模型

手动演示不应写死在 Activity 里，建议单独引入“室内演示脚本”。

### 8.1 数据结构

```json
{
  "route_id": "manual_demo_wudaokou_west_to_2f_tata",
  "venue_id": "venue_bj_wudaokou_shopping_center_demo",
  "target_poi_id": "poi_f2_tata_door_demo",
  "start_floor_id": "F1",
  "steps": [
    {
      "id": "step_001",
      "floor_id": "F1",
      "instruction": "从西门进入，沿一层通道直行至西侧通道转角",
      "expected_action": "up",
      "current": { "label": "F1 西门入口", "x": 6.0, "y": 23.7 },
      "next": { "label": "F1 西侧通道转角", "x": 25.9, "y": 23.8 }
    },
    {
      "id": "step_002",
      "floor_id": "F1",
      "instruction": "左转后沿主通道前往一层上行扶梯",
      "expected_action": "left",
      "current": { "label": "F1 西侧通道转角", "x": 25.9, "y": 23.8 },
      "next": { "label": "F1 上行扶梯口", "x": 28.9, "y": 9.3 }
    },
    {
      "id": "step_003",
      "floor_id": "F1",
      "instruction": "乘扶梯上行至 F2",
      "expected_action": "floor_up",
      "current": { "label": "F1 上行扶梯口", "x": 28.9, "y": 9.3 },
      "next": { "label": "F2 扶梯出口", "x": 28.4, "y": 6.0 }
    }
  ]
}
```

### 8.2 字段说明

- `instruction`：当前步骤给用户展示的提示文案
- `expected_action`：当前步骤允许推进的动作
- `current`：当前节点
- `next`：执行动作后要移动到的节点
- `floor_id`：当前步骤所在楼层

### 8.3 支持的动作

```text
expected_action =
  "up" |
  "left" |
  "right" |
  "down" |
  "floor_up" |
  "floor_down"
```

## 9. App 状态口径

为避免大改现有 `NavState`，推荐保留原状态枚举，但修改室内主流程解释。

### 9.1 当前主链路使用的状态

- `INDOOR_READY`
  - 室内底图和手动脚本已就绪
  - 等待开始手动演示或已进入手动演示待机态

- `INDOOR_ROUTE_READY`
  - 手动演示脚本已激活
  - 当前提示、当前位置和目标点已展示
  - 等待用户通过方向键或上楼 / 下楼键推进

- `ERROR`
  - 演示脚本异常、楼层切换异常、底图异常

- `ABORTED`
  - 用户中止演示

### 9.2 暂时保留但默认不进入的状态

以下状态仍保留在代码中，但在当前默认室内模式下不走主流程：

- `INDOOR_CAPTURING`
- `INDOOR_LOCATING`
- `INDOOR_LOW_CONFIDENCE`
- `INDOOR_ROUTING`

这些状态属于保留的云端链路，不属于当前室内 Demo 主演示路径。

## 10. UI 方案

### 10.1 顶部状态卡

顶部状态卡建议展示以下内容：

- 当前模式：`室内手动演示`
- 当前楼层：`F1 / F2 / B1`
- 当前提示：如“前方右转”
- 当前节点：如“F1 扶梯口”
- 目标节点：如“2F A 店门口”
- 错误或纠错提示：如“当前应按右键”

### 10.2 地图展示

地图层继续使用已接入的高德室内底图控制器，展示：

- 当前楼层底图
- 当前点位 marker
- 目标点 marker
- 当前楼层的路径折线

建议高亮规则：

- 已完成段：灰色
- 当前待执行段：蓝色
- 目标点：红色

### 10.3 底部操作区

当前 `manual_demo` 主流程不再把白色路线预览卡作为首层地图展示，室内主视觉交给高德室内底图和 App 业务覆盖物。

室内主操作区收口为：

1. 方向键区
2. 上楼 / 下楼按钮区
3. 重置与退出室内

推荐按钮集合：

- `上`
- `左`
- `右`
- `下`
- `上楼`
- `下楼`
- `重置室内演示`
- `退出室内`

### 10.4 Debug 面板

Debug 面板仍保留，但默认不暴露云端室内按钮为主流程。

建议分组：

- `当前室内模式`
  - `manual_demo`
  - `cloud_relocalization (disabled)`

- `手动演示调试`
  - 当前脚本 ID
  - 当前步骤 ID
  - 上一步 / 下一步日志
  - 是否允许回退

- `保留云端链路`
  - `Capture & Locate`
  - `Request Route`
  - 默认隐藏在二级区域或标注“当前不使用”

- `室内点位标注（Debug）`
  - 开启后点击高德室内底图记录当前楼层、`x/y`、`lat/lng`
  - 输出 `point_id,type,floor_id,x,y,lat,lng,route_node_id,photo_ref,remark`
  - 用于现场复核和回填 `manual_demo` 脚本，不代表正式场馆包已完成

## 11. 现有代码复用建议

当前仓库里已经有可复用基础：

- `IndoorBasemapController`
  - 可继续承载高德室内底图、楼层切换和室内覆盖物

- `IndoorBusinessOverlay`
  - 可继续作为当前点、目标点、路径线的渲染输入

- `NavState`
  - 可暂不大改，只调整室内状态的解释与使用方式

- `LocalizationApiClient`
  - 暂时不删
  - 在 `manual_demo` 模式下不触发

## 12. 建议新增模块

建议新增一个轻量室内演示控制器：

```text
ManualIndoorDemoController
```

职责：

- 加载手动演示脚本
- 记录当前步骤索引
- 校验按键输入是否正确
- 生成下一条提示文案
- 产出当前地图覆盖物
- 产出楼层切换指令

建议新增一个手动演示状态模型：

```text
ManualIndoorDemoState {
  mode: "manual_demo"
  route_id: string
  current_step_id: string
  current_floor_id: string
  instruction: string
  expected_action: string
  can_step_back: boolean
  is_arrived: boolean
}
```

## 13. 验收标准

满足以下条件时，手动室内演示模式可视为可用：

- `Enter Venue` 后默认进入室内手动演示模式
- 不依赖云端定位结果也能完整演示一条室内路线
- 方向键按对时，地图、提示、当前位置同步推进
- 上楼 / 下楼按对时，室内底图切到对应楼层
- 错误按键不会推进，并给出明确提示
- 云端定位和路径规划代码仍保留，但默认不触发
- 演示人员不展开 Debug，也能完成一次完整室内演示
